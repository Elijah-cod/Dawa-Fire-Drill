# Checkpoint A: design review

Review the [design brief](../../design/README.md), [exact screen copy and states](../../design/screens.md), and [responsive prototype](../../design/prototype/README.md). The [Figma file](https://www.figma.com/design/miYdEWIJdzCwcEEECAqUpW/Dawa-Fire-Drill-%E2%80%94-Phase-1-Design) contains the four planned pages but no approved frames; its generated drafts were removed because they invented quantities and costs. The static prototype is the current screen review artifact.

- [ ] The county planner can complete the three-minute path from Overview to a ranked action without instruction.
- [ ] The ranked action order, budget ceiling, selected set, and cut line are clear. The copy does not imply an LLM made the ranking.
- [ ] The district pharmacist can distinguish an eligible transfer from an excluded one, including shelf life and availability constraints.
- [ ] The facility in-charge can compare the bin-card photo with every editable field before confirming a save.
- [ ] Every decision view shows the synthetic-data and illustrative-output notice.
- [ ] Critical, Watch, Stable, and Unknown remain distinct without color. The map has an equivalent ordered list.
- [ ] Empty, loading, error, offline, and partial-data copy covers every key screen.
- [ ] Mobile, tablet, laptop, and wide layouts preserve readable text, 44px targets, and no horizontal page scroll. The mobile map is a sheet and tables become cards.
- [ ] English and Swahili string structure, theme behavior, keyboard focus, and reduced-motion rules meet the brief.
- [ ] The partial Figma file and static prototype fallback are acceptable for this checkpoint, or native Figma completion is requested.

Frontend implementation remains blocked until the user replies exactly `DESIGN APPROVED`. Record the approval in `APPROVAL.md` with the reviewed artifact references.
