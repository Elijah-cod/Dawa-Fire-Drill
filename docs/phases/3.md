# Phase 3 frontend

In progress. All data is synthetic; model outputs are illustrative and unvalidated.

The local demo proxy must obtain its server-only synthetic token from its environment, never expose it to the browser, and query the authenticated backend demo-capabilities endpoint before presenting role switching. Development fixtures and the later deployment sign-in design remain outstanding.

The authenticated backend demo session endpoint returns the validated role and scope, not the bearer token. A rejected or missing token must be presented as an unavailable session; no production sign-in flow has been designed.

The initial same-origin client covers session, capability and national overview reads with OpenAPI-generated response types. The page uses the controlled-session provider and the typed proxy client in demo mode, or synthetic fixtures in development. The remaining API operations still need typed clients.

The current work is an incomplete national-view scaffold: the schematic grid, an adapter-driven `AuthProvider`, a local/staging proxy, and backend-generated synthetic fixtures for four roles are present. The mock currently covers only the overview and Kisumu run. The proxy is off unless server-only demo settings are supplied and refuses production. Staging must be protected by an external access control because the demo proxy uses a privileged synthetic identity. The app has no sign-in screen; a real deployment sign-in and session design requires separate approval.

The scaffold has not passed a screen review. Its national copy and persistent synthetic notice now support English and Swahili, and theme controls offer system, light, and dark. A mobile full-screen schematic sheet and county list are present. Compared with the approved design, it still lacks bottom navigation, complete role views and all required states, and the remaining screens. The national scaffold and its mobile sheet passed initial axe checks with no serious or critical violations on the four viewport projects. Visual regression baselines, full keyboard journeys, offline queue, Lighthouse budgets and the complete real-backend demo remain outstanding.
