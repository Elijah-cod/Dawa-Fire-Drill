# Phase 3 frontend

In progress. All data is synthetic; model outputs are illustrative and unvalidated.

The local demo proxy must obtain its server-only synthetic token from its environment, never expose it to the browser, and query the authenticated backend demo-capabilities endpoint before presenting role switching. Development fixtures and the later deployment sign-in design remain outstanding.

The authenticated backend demo session endpoint returns the validated role and scope, not the bearer token. A rejected or missing token must be presented as an unavailable session; no production sign-in flow has been designed.

The current work is an incomplete national-view scaffold: the schematic grid, a controlled-session `AuthProvider`, a local/staging proxy, and backend-generated synthetic fixtures for four roles are present. The mock currently covers only the overview and Kisumu run; it is not yet wired to the page. The proxy is off unless server-only demo settings are supplied and refuses production. Staging must be protected by an external access control because the demo proxy uses a privileged synthetic identity. The app has no sign-in screen; a real deployment sign-in and session design requires separate approval.

The scaffold has not passed a screen review. Compared with the approved design, it still lacks live planning data and role views, English/Swahili switching, bottom navigation, the mobile map sheet, complete loading/error/offline/partial states, and the remaining screens. Screenshot comparison, visual regression baselines, axe, full keyboard journeys, offline queue, Lighthouse budgets and the real-backend demo remain outstanding.

The approved county addendum and the user's 2026-11-07 direction allow an original 47-county schematic grid while boundary rights are unresolved. It is not a map of geographic shapes. See `docs/data-assumptions.md` for the exact geoBoundaries metadata and why no geometry is included. No screen is complete or screenshot-approved yet.
