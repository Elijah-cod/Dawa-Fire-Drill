# Phase 2b: Kenya counties and Kisumu pilot

Work in progress. All operational and financial values are synthetic; outputs are illustrative and unvalidated. Official county and sub-county names are geographic reference labels, not synthetic observations.

The intended demo asks: “What breaks first in Kisumu if donor-funded logistics support drops 40%, and what is the cheapest fix?” The shock and all planted cases are synthetic assumptions, not claims about Kisumu's donor dependence or health outcomes.

The proposed national, sub-county and facility experiences and their responsive states are specified in `docs/design/addendum-counties.md`. No frontend implementation is included.

A seeded planning generator now creates synthetic all-sector budget and release proxies for all 47 county labels and preserves published national totals. County allocations are invented and are not county-specific observations or health budgets; the generator is not yet exposed or persisted. See `docs/data-assumptions.md` for the source and limitations.

An isolated Kisumu panel generator contains 40 invented facilities across the seven named sub-counties, ten tracers including antiretrovirals and antimalarials, synthetic consumption, opening stock, a route, and three planted demo cases. A Kisumu-only simulator uses the panel's explicit synthetic stock and demonstrates the planted cases in the 40% shock; sub-county counts are checked against facility results. Authorized planners can read the saved panel, but the simulator is not yet connected to persistent runs or APIs, and mitigation selection is not yet connected to the planted transfer.

The optimizer's ordering model now expresses benefit and input-order precedence directly in OR-Tools, avoiding a combinatorial tie-resolution failure at the 50-candidate request limit.

Migration `0010_county_snapshots` adds a separate immutable snapshot table with forced Postgres row-level security requiring both country and county transaction contexts. Its pilot constraint permits facility snapshots only for Kisumu. Non-superuser tests cover missing context and cross-county reads and inserts; the migration is tested up and down. This does **not** yet make legacy scenarios, jobs, funding or capture county-isolated.

The county snapshot repository sets and filters both scope values for every read and creation. It stores one synthetic planning record per county and a facility snapshot only for Kisumu, with idempotent seed/version keys. A local PostgreSQL smoke test loads all 47 planning records before running the synthetic Kisumu simulation; its ten-second bound is a regression check, not a production capacity guarantee.

Authentication validates optional server-controlled county and national-planning claims; facility and pharmacist roles cannot receive the national-planning flag. The county planning overview requires explicit national scope, county planning reads require the matching county or national scope, and the Kisumu pilot read requires Kisumu scope and a planning role. Missing planning snapshots remain visibly absent, not zero. Legacy country-only endpoints do not yet enforce these claims, so they must not be treated as county-isolated.

A scoped facility endpoint returns only the requested synthetic facility, stock and consumption; facility-role users can request only the facility in their trusted claim. National-planning permission alone does not grant facility access.

Implementation sequence:

1. Establish the official county and Kisumu sub-county reference directory.
2. Add country/county tenancy and fail-closed role scopes across persisted records and API access, including migrations and cross-county tests.
3. Seed planning-only county aggregates and the Kisumu synthetic facility panel with reproducible planted cases and cited calibration limitations.
4. Connect county-scoped runs, roll-ups, funding, and modeled mitigation; verify stockout and redistribution cases and benchmark 47 counties.
5. Write the design addendum and demo notes, run the full local and CI gates, and prepare the requested review.
